# Phase 2 — Organization and Authorization Foundation

Tanggal: 2026-11-27. Status: **Phase 2 implementation and technical acceptance gate complete locally. Non-superadmin access remains deny-by-default until its common capability set is approved.**

## Implemented

- Organization is now represented as native PostgreSQL relations: `areas → regions → branches → service_areas → workzones`. Parent-scoped natural-code uniqueness is used below the top area. Workzone identity remains parent-scoped; no global uniqueness or alias matching was invented.
- Added generic `roles`, `permissions`, and `role_permissions`; `users.role_id` replaces the scaffold's hardcoded legacy role strings. The approved role names are seeded as catalog entries only; no permission is seeded, so no old role is implicitly mapped or granted.
- Added an idempotent seed migration for the six owner-approved role names. It inserts only role code/display-name records; it creates no permissions, grants, or users. Existing codes are left unchanged on conflict.
- Added `user_scopes` with typed nullable target FKs for each hierarchy level, an exactly-one-target check, and a `UNIQUE NULLS NOT DISTINCT` constraint to prevent duplicate grants while allowing overlapping ancestor/descendant grants.
- Added `loadAuthorizationContext`, which resolves only unrevoked, unexpired session token hashes for active users/roles and loads role permissions. Raw cookie tokens are not accepted by the database lookup.
- Added reusable `ticketAccessPredicate`: it returns SQL `FALSE` without the required permission; otherwise an `EXISTS` hierarchy predicate enforces explicit global scope or the union of any user grants, excludes inactive ancestors/workzones, denies unmapped tickets, and avoids grant fan-out. Callers compose requested filters with this predicate using `AND`.
- Added `/auth/csrf`, `/auth/login`, `/auth/logout`, and `/auth/me`. Login requires exact configured Origin and a timing-safe double-submit CSRF token, normalizes username, verifies Argon2id (with a dummy hash for missing identities), applies bounded per-account and per-connection-IP throttles, issues a random 32-byte opaque token in a `__Host-` Secure/HttpOnly/SameSite=Lax cookie, and stores only SHA-256. Logout revokes the matching live hash; `/me` re-resolves current active session, own username/display name, role, scope version, and permissions. It clears invalid/stale cookies while preserving the cookie on database outage.
- API auth routes are composed through a route factory so requests can be tested with `app.handle` and a rollback-only database transaction. DB-specific identity/session statements live in the DB package.
- Added a reusable Elysia `requirePermission` macro. Each protected route resolves session/role/permission once, returns 401 for absent/stale sessions, 403 for missing capability, and injects the typed `authorization` context for its handler. Guarded and auth responses use `private, no-store`.
- Added `appendAuditEvent` to the DB package. It accepts the caller's transaction handle so state changes and their audit event commit atomically, and limits metadata values to scalar JSON. User/organization writers use operation-specific metadata allowlists; the audit UI intentionally withholds unstructured metadata. Retention remains pending owner policy.
- Added exact incident detail `GET /tickets/:incident`, guarded by the proposed (unseeded) `tickets.read` permission. It normalizes the canonical incident key, applies `ticketAccessPredicate` in the same SQL query, returns 404 for absent and out-of-scope tickets, and selects an explicit non-PII DTO without raw `detail`, summary, customer, or service number fields. It exposes stored SLA/TTR values as-is and calculates no unverified rules.
- Added `GET /tickets` with validated exact search (incident/service number), canonical lifecycle, stored bucket, exact raw status, and optional hierarchy ID filters. All filters intersect with the same server-derived permission/scope predicate. The response is a bounded 50-row default / 100-row maximum explicit non-PII projection and omits totals to avoid extra count queries. Keyset ordering is `reported_at DESC NULLS LAST, id DESC`; the cursor preserves PostgreSQL microseconds, is HMAC-signed, and binds user, scope version, global grant, permission set, and filter fingerprint. Cursor verification fails closed after scope/permission/filter change or signature tampering. The signing key is process-local random, so restart invalidates outstanding cursors; a future multi-replica deployment needs a shared secret. No permission grant was seeded.
- Existing `user_workzones` and obsolete scaffold fields were removed in migration `0001_wild_shadow_king.sql`. This local database had no users, grants, masters, or tickets before migration; only the internal `sync_revision` row existed.
- Added a native Bun SQL/Drizzle migrator and `bun run db:migrate`. The existing `0000` baseline was recorded in `drizzle.__drizzle_migrations` using its verified SQL SHA-256 and journal timestamp, then migration `0001` was applied by the Drizzle migrator.
- Added superadmin-only User Management API routes for bounded list/detail, account creation with a selected role and Argon2id initial password, hierarchical scope/global-scope updates, and soft deactivation. Mutations require Origin + CSRF checks and revalidate the active global superadmin in a serialized transaction; scope edits revoke sessions and bump `scope_version`; last active global superadmin and self-protection guards are enforced. Audit metadata contains only allowlisted operational values.
- Added a responsive light/dark User Management screen with bounded pagination, cascading searchable scope selection, create/edit/deactivate flows, and permission-aware navigation. The UI does not replace API authorization.
- New account role selection is supported at creation. Existing role changes and password reset/change flows are not implemented; initial credentials must be delivered to the user through a separate secure channel.
- Added read-only `GET /api/admin/organization/child-impact` for superadmin/global-scope preview before adding a child to the hierarchy. It validates active parent ancestry, returns global and inherited-scope user counts, and returns a bounded keyset-paginated user list with matched grant levels. Overlapping grants count a user once. This is a snapshot only; future mutations must recompute impact in the same write transaction and compare the acknowledged preview.
- Added `/admin/organization`, a superadmin-facing read-only preview screen. It cascades the five hierarchy levels, supports code/name narrowing, shows global/inherited impact counts and a keyset-paginated affected-user list, and shares the saved light/dark theme. The screen performs no hierarchy mutation; all authorization remains server-side.
- Added `POST /api/admin/organization/children` and a confirmation form. A five-minute signed preview token binds the active actor, child level, parent, affected-user count, and fingerprint. The transaction serializes with user-scope administration, revalidates active superadmin permission and active parent ancestry, refuses changed impact, creates the normalized child code, increments `scope_version` and revokes sessions for affected users, and appends audit atomically. Reauthentication, exact Origin, and CSRF are required. Parent moves and deactivation are intentionally not included.
- Added bounded active node search and Region/Branch/Service Area/Workzone reparent preview + mutation. It binds source and destination to a five-minute token, reviews the scope-affecting user set, rechecks current parent and impact under the user-admin serialization lock, rejects natural-code collisions, moves only the parent FK, bumps affected scope versions, revokes sessions, and audits transactionally. Area stays a root; physical deletion remains unavailable. Reports retain the documented current-hierarchy historical interpretation.
- Added `GET /api/admin/audit-events` and `/admin/audit`, restricted to active global superadmin with `audit.read`. The endpoint returns a bounded UUIDv7 keyset page with only event ID, actor ID, action, target ID, request ID, and timestamp; it never selects free-form metadata. The UI inherits the saved light/dark theme and contains no export or mutation control.

## Boundaries and open work

- Phase 2 implementation and its documented technical gate are complete locally: sessions, RBAC guard, five-level hierarchy, scoped access predicate, User Management, child creation, reparent, bounded audit read, authorization/revocation integration tests, and authenticated browser flows all passed. No production/cutover readiness is implied. The owner-approved superadmin capability migration is applied locally; no persistent account exercises those grants. Other roles have no capability grant and remain safely deny-by-default until their common capability set is approved. Operator bootstrap remains unverified.
- A data-only migration `0003_seed_superadmin_capabilities.sql` declares ten owner-approved permissions and grants them only to `superadmin`. It is applied to local PostgreSQL 18.7 `dompis_v3` (10 permissions, 10 superadmin grants, zero grants to other roles); no user data was changed. The three middle roles are equivalent to one another but their common capability set is still open; helpdesk/teknisi remain deferred. See `Authorization-Capability-Discovery.md` and ADR-036/037.
- A read-only source audit found six legacy role keys (`superadmin`, `admin`, `helpdesk`, `teknisi`, `senior_leader`, `admin_branch`); the owner-approved v3 names are `superadmin`, `team_leader`, `helpdesk`, `teknisi`, `senior_leader`, and `officer` (`admin` → `team_leader`; `admin_branch` → `officer`). Evidence and the distinction between names and authorization are in `Legacy-Role-Discovery.md`. Six role catalog rows and superadmin grants are seeded locally. The guarded bootstrap can create a first global superadmin; no account has been created.
- Static legacy guard analysis now records contradictory role equivalence, user administration, audit, and scope behavior in `Authorization-Capability-Discovery.md`. Follow-up source inspection found legacy hard-delete and insecure password-reset behavior; neither is carried forward. Superadmin user administration now supports bounded list/detail, create with selected role and Argon2id initial password, hierarchical scope changes, and soft deactivation. Existing role changes and password reset/change are not implemented. Audit metadata is allowlisted; retention policy remains open.
- No legacy master/user/scope data was migrated. New top-level-area crosswalk, Workzone dictionary, old-to-new role mapping, account activation, and effective-scope parity remain Phase 0C blockers.
- No Workzone alias table was added. The 74 unmatched legacy keys remain unresolved pending an approved crosswalk.
- The candidate schema migration includes drops of empty scaffold structures. Do not apply this migration line to a database containing application data; production requires a reviewed additive/copy/backfill plan and backup.
