## Verified legacy source observation — closed-window overflow replay

- Evidence: `dompis_v2/lib/external-db/qosmic-bridge/window-planner.ts:110-113` says a window's pages must be buffered before yielding so an overflow can be discarded and bisected without already-yielded duplicates. In `dompis_v2/lib/external-db/qosmic-bridge/nossa.ts:195-202`, however, each page is yielded before overflow is checked at `:204-209`; overflow then recursively scans the two halves at `:219-232`.
- Impact: the overflow scan is not an atomic snapshot. Exact-row SHA-256 deduplication at `:196-200` suppresses byte-equivalent rows but cannot reconcile two different versions of the same incident if upstream changes during the original scan and split replay. Downstream final state can therefore depend on arrival order unless the consumer has its own validated source-version conflict rule; none is inferred here.
- Classification: verified implementation/comment discrepancy by static read-only inspection, not a server-contract finding, demonstrated incident of data loss, benchmark, or production observation. No legacy behavior is approved for copying into v3.
- Greenfield implication: use documented bounded-window and coverage rules only after real endpoint fixtures validate them. Require a stable reconciliation/conflict strategy and tests for page drift, same-incident mutation during split, exact duplicate pages, and dense timestamp ties before claiming complete scan semantics.
- Status: recorded for architecture/acceptance planning. No legacy source changed and no tests or endpoint requests were run.
