# Security baseline

## Kebijakan v1.3 (berlaku atas seluruh dokumen)
Pemilik mengizinkan agent lokal mengakses MySQL dan PostgreSQL, read dan write. Akses aktual bergantung pada credential, jaringan, privilege dan sandbox agent; jangan mengakali kontrol. Gunakan Database-Access.md sebagai kebijakan otoritatif. Read produksi yang ringan dan write rutin terukur dalam target yang telah didaftarkan tidak memerlukan konfirmasi per query. Operasi produksi berisiko tinggi, perubahan schema produksi, bulk correction, freeze/cutover dan tindakan irreversible memerlukan persetujuan runbook khusus. Source legacy tetap read-only; database bukan source code. Discovery tidak mengubah data bisnis produksi. Semua rancangan teknis termasuk DDL, jumlah tabel/index dan alias adalah kandidat, bukan kontrak tetap. Direct matching Workzone diutamakan; buktikan keunikan global setelah normalisasi, jika ambigu gunakan pembeda yang terverifikasi, jangan menebak. Alias hanya bila terbukti diperlukan. Requirement bisnis, integritas historis, keamanan dan stack tetap wajib. Lihat Discovery-Protocol.md dan Decision-Log.md.


Threat model: stolen session, horizontal access by incident UUID, report/export leakage, compromised upstream payload, rate-limit abuse, SQL/XSS/CSRF, secrets and backup exposure, worker resource exhaustion. Internal app still requires full authentication and authorization.

## Controls
- Username canonical lower/trim, Argon2id via reviewed Bun-compatible implementation (benchmark memory/time), unique salt, no default password; migrate only verified legacy hashes with rehash on login or reset, never plaintext. Generic login errors, bounded per-account/IP throttling with atomic in-flight reservations before database/hash work; trusted proxy only. MFA for privileged users recommended. Disable technician accounts and inactive users by default.
- Opaque random 32-byte token in `__Host-dompis_session` cookie Secure HttpOnly SameSite=Lax Path=/, no Domain, hash SHA-256 in sessions. Rotate at login/privilege change, revoke at logout/password change/disable; absolute expiry initial 8h, idle expiry optional with throttled writes. No access token localStorage. CSRF token + strict Origin for mutations (including login/logout), reject cross-site; same-origin deployment, no wildcard credential CORS. TLS only; CSP default-src self, frame-ancestors none, object-src none, narrowly scoped connect-src; HSTS after TLS validated; nosniff; Referrer-Policy strict-origin or no-referrer. No browser third-party analytics by default.
- API responses apply `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, and `Referrer-Policy: no-referrer` globally. CSP and HSTS remain deployment-layer controls; HSTS must wait until TLS is validated.
- API readiness responses use `Cache-Control: no-store` because their database/auth configuration state can change while a deployment is running.
- Every API response carries a server-generated `X-Request-ID`; unhandled errors use generic `not_found`, `invalid_request`, or `internal_error` bodies with the same ID. Server logs may correlate 5xx by request ID and error type/code only; never log the raw error message, stack, SQL, or request payload.
- Server checks active account/session + permission + resolved workzone on every protected endpoint, including reports, detail, export, history, SSE connection/renewal and admin mutations. Explicit global grant, empty/unknown scope deny, intersect requested filters. Scope change invalidates session/stream or rechecks within bounded interval. Superadmin global not automatic solely from URL role; no frontend-only authorization. IDOR test on UUID and incident.
- Drizzle parameterization, schema validation max length/range/body/limit; sort enum; query timeouts and concurrency. Sanitize CSV formula injection for leading = + - @ tab CR and leading spaces; proper escaping, PII export explicit permission audited; cap rows, no unbounded XLSX memory. Do not use raw HTML or unsafe URL from source. API returns minimum DTO, never raw detail JSON by default. Error generic with request ID, no query/stack. Cache private no-store for sensitive responses, no CDN shared cache.
- API server request bodies are capped at 16 KiB while the current API accepts only small auth JSON bodies. Revisit with an explicit contract before adding routes that need larger bodies; large sync/import payloads belong to the separately bounded worker path.
- Worker fixed HTTPS origin/path allowlist, no arbitrary URL from user; disable redirects or verify same origin; secret only server env/secret file 0600; no token in URL/log. Payload max size, page limit, validate schema, bounded retries, fail closed on malformed response. Limit quarantine size/retention, restrict role access, redact PII in logs. Audit operator replay and rule changes.
- PostgreSQL private network, firewall only API/worker host, SCRAM, TLS if crossing network, distinct non-superuser roles, no public 5432, encrypted backups and access restricted, test restore. Systemd non-root, minimal fs access; package versions pinned, dependency audit/secret scan in CI; no .env/fixtures with real PII in git. Production configs separate staging.
- Legacy review: stress-test.js includes literal/default credential examples; treat as exposed if valid and rotate; remove default fallback creds, synthetic test only. proxy.ts has hand-written JWT verifier; replace with simpler opaque sessions, not copy. server.ts logs and ignores uncaughtException; new process fail-stop/restart on unknown fatal state. No secret values reproduced in docs.

## Release tests
Unauthorized list/detail/report/export/SSE denied; cross-workzone/empty scope; role downgrade/session revocation; expired token; CSRF origin mismatch; login brute force; malicious sort/filter/CSV/cursor; upstream invalid JSON/oversize and redirect; logging redaction; DB privileges; concurrent export and ingestion limits; backup access/restore. No production deploy if critical/high unresolved. Use security review and dependency scanning, do not claim security proven by static design.

## Migration-specific controls (v1.3)
Read-only MySQL restore access; never open a public DB listener. Dedicated temporary ETL PG role, no superuser; revoke after cutover. Encrypt dump, transfer, manifest and archive at rest, restrict access and retention; full backup may contain sensitive legacy fields, never include in Git, agent context, logs or synthetic fixtures. Hashes and IDs not anonymous; restrict them too. Archive not exposed by generic SELECT/API; historical detail only if approved scoped endpoint and field allowlist, audit reads/exports. Reject unmatched scope by default. Verify backups before extraction, do not repair/delete corrupt source as part of import. Do not execute production migration on agent startup. Check credentials for leakage and rotate if exposed.

## v1.3 hierarchy RBAC
Read Organization-Scope.md as mandatory scope policy. Action permission AND current scope, even for admin; global explicitly provisioned only by authorized security administrator, never a client flag. No generic grant escalation endpoint. MVP only authorized superadmin with global/admin-management capability can mutate hierarchy and grants; require reauthentication for elevation/global, audit before/after without PII, prohibit self-elevation and last-admin lockout. User scope edits lock user row and increment scope_version in same transaction; rare master/alias edits use serialized admin transaction and increment affected users (all users acceptable initially). Recheck active account, session and scope at each request. On SSE revocation disconnect/invalidate; SSE sends only generic revision, no ticket data; reauthorize reconnect/heartbeat, no unauthorized detailed counts. Cursor signed + current scope version and filter fingerprint; export revalidate before every chunk and abort if changed. UI clears prior scoped data on downgrade; do not use client cache as auth. DB account privileges: only approved API admin code updates master/grants, worker reads aliases and writes tickets, migrator separate; RLS not asserted. Test union overlap, direct ID guessing, sibling/parent filter expansion, cross-area grant, null grant FK, disabled path, scope revision race, unauthorized parent reparent, global without PII permission, export/SSE revocation, legacy access broadening. No silent privilege broadening.
