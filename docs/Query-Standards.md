# Query & Performance Standards — v1.3

## Kebijakan v1.3 (berlaku atas seluruh dokumen)
Pemilik mengizinkan agent lokal mengakses MySQL dan PostgreSQL, read dan write. Akses aktual bergantung pada credential, jaringan, privilege dan sandbox agent; jangan mengakali kontrol. Gunakan Database-Access.md sebagai kebijakan otoritatif. Read produksi yang ringan dan write rutin terukur dalam target yang telah didaftarkan tidak memerlukan konfirmasi per query. Operasi produksi berisiko tinggi, perubahan schema produksi, bulk correction, freeze/cutover dan tindakan irreversible memerlukan persetujuan runbook khusus. Source legacy tetap read-only; database bukan source code. Discovery tidak mengubah data bisnis produksi. Semua rancangan teknis termasuk DDL, jumlah tabel/index dan alias adalah kandidat, bukan kontrak tetap. Direct matching Workzone diutamakan; buktikan keunikan global setelah normalisasi, jika ambigu gunakan pembeda yang terverifikasi, jangan menebak. Alias hanya bila terbukti diperlukan. Requirement bisnis, integritas historis, keamanan dan stack tetap wajib. Lihat Discovery-Protocol.md dan Decision-Log.md.

Correctness and authorization before speed. Do not translate MySQL queries mechanically; design PostgreSQL query from approved membership and scope. Drizzle typed select/conditions; parameterized SQL fragments for advanced PostgreSQL when justified. Never concatenate untrusted filters/order. All protected queries require scope + permission and explicit fields.

## 1. Patterns
- Shared authorized workzone subquery per Organization-Scope.md. Filter on `tickets.workzone_id`, not names or duplicated ancestors; EXISTS/IN prevents grant fanout. Small dimension join for aggregation; no N+1 per ticket/alias. Global explicit; unknown scope separate.
- Exact incident unique lookup, service_no exact; keyset tuple `(reported_at,id)` or `(closed_at,id)` matches ordering and partial predicates; null anomaly separate. Stable tie-breaker, signed cursor current scope/filter/version. No unbounded list or deep OFFSET local. Upstream offset mandated by contract is exception.
- Use half-open native timestamptz ranges with approved timezone; no DATE(column), casts or LOWER on indexed column in WHERE unless deliberate expression index. Select only required columns; JSONB not default projection/filter. Count via COUNT(*) FILTER, grouped dimensions; avoid per-widget full scans or Bun arrays. List/overview/drilldown same predicate; same-response consistent asOf; cross-page not snapshot guarantee. Bounded stream CSV with scope checks and backpressure.
- Ingestion sort incident, dedup, short transactions, changed-only update; do not hold DB locks during HTTP. Reconcile legacy archive separately; no index per column, no periodic full rewrite or heartbeat updates. Batch alias lookup from small master table; invalidate on correction. Separate bounded pools API/worker/migration, statement/lock/idle-in-tx timeouts tuned from staging, no pool per request. Retry only transient errors bounded, no retry storm.

## 2. Baseline index budget
Seven tickets secondary indexes (DDL); unique incident and PK separate. Master unique parent+code index supports path traversal; user_scopes unique user-leading index supports resolver; alias unique triplet for point mapping. No GIN, BRIN, closure table, partition, Redis, materialized view or denormalized geography unless measured. Sequential scan may be efficient for broad aggregation; do not force index scans. Use actual query shape and prepared statement plan; literal trusted partial predicates, bound dynamic values. FK reverse indexes only after deletion/admin/query pattern profiling. Document each added index read benefit, write/WAL/storage cost and rollback.

## 3. Performance gate
Staging representative 1.2m and 3.5m synthetic tickets; realistic distributions, hot/cold, geography skew, narrow/branch/area/global scopes, overlapping grants, open vs closed, date range, export, sync concurrency. Capture EXPLAIN (ANALYZE, BUFFERS) for SELECT in staging, pg_stat_statements where enabled, pool wait, I/O, WAL, rows, p50/p95/p99, error and freshness; measure cold/warm separately. Do not execute EXPLAIN ANALYZE writes in production. Load 20/80/200 VU with realistic mixes and rate-limited sync mock. Initial PRD goals (not measured): detail p95 ≤200 ms, list ≤350 ms, overview/rekap ≤1 s, semesta 31 days ≤2 s under agreed workload. If miss: profile, optimize query/index and retest before adding infra. Record hardware/dataset/config, plan before/after, tests and limitations in Handover. SSD/NVMe recommended; separating CT on same HDD does not remove physical contention. Backup/restore and autovacuum/WAL sizing verified before production.

## 4. Review checklist
Every query has named purpose, explicit scope, validated filters, projection, limit, correct time basis, index justification, no N+1 and tests for empty/multi-level scope, duplicate counts and SQL injection. Compare old approved result membership, not old execution path. Do not publish fabricated benchmark or copy old query. Document ADR only when actual complexity warranted.
