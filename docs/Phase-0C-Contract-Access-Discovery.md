## 1C. Semesta recurring/GAUL source behavior

The V2 source query tests a valid nonblank `service_no` other than `NN` for at least one different incident within ±60 calendar days of a candidate incident's `reported_date_dt`. Both the candidate and related incident must also fall inside the selected report range. It groups by `(service_no, workzone)`, counts distinct candidate incidents, sorts by occurrence count and returns at most 100 groups. The current total sums those returned groups, so groups beyond the top 100 are omitted from the displayed GAUL total. The related-incident `EXISTS` comparison does not require the same Workzone, and ordering ties have no secondary deterministic key. The separate LAPUL path currently returns an empty list because its source comments state that duplicate rows cannot exist under the one-current-row-per-incident projection.

This is implementation behavior only, not an approved GAUL definition. The PRD requires recurring only when the source fields exist and the lookback is approved. A v3 design must explicitly decide whether recurrence crosses Workzones, how service numbers are normalized, whether current-state incidents or event history are counted, whether filtering the report range should truncate the lookback, what minimum occurrence means, and whether the result is a complete count or a capped display list. Never reproduce the legacy top-100 undercount as the KPI total; if v3 needs top services, compute the aggregate total separately from the capped detail list.

## 4. Legacy user effective-scope baseline

`app/helpers/ticket.helpers.ts:20-86` resolves leaf names by unioning `user_sa`, `user_area`, `user_branch` and `user_region`, then deduplicates names with a JS `Set`. Other code uses direct `users.region_id/branch_id/area_id`; some API paths have role-based or `globalScope` exceptions. This is not a single consistent permission contract.

Read-only aggregate over the current MySQL hierarchy reproduced the four-junction union by expanding each grant to service-area leaves, deduplicating `(user_id, id_sa)`:

- 22,392 expanded user-leaf pairs before overlap de-duplication; 17,969 distinct pairs after de-duplication (4,423 overlap rows removed).
- 3,835 distinct users have at least one junction-derived leaf; total users=4,098, so 263 users have no junction-derived leaf. They may have direct FK scopes or no scope; this result does not classify them.
- User/parent orphan pairs: 0 in each of the four junction tables. `user_sa` has 2 null user IDs and 2 null SA IDs; null row overlap is unknown and null pairs do not create leaf access. Other three junction tables have zero null user/parent fields.
- This is a junction-only legacy baseline. Full per-user difference against direct FK-derived scopes, explicit role exceptions, and the proposed new grants was not accepted as validated; no new target grant set or owner-approved policy exists. User identifiers/names were not output.

On 2026-11-27, one read-only transaction expanded the four junction grants **and** `users.region_id/branch_id/area_id` through the legacy hierarchy to deduplicated service-area leaf pairs. It found 17,969 junction-derived pairs across 3,835 users; 611,066 direct-FK-derived pairs across 4,038 users; 16,139 overlaps; 1,830 junction-only pairs; and 594,927 direct-FK-only pairs. Their union was 612,896 pairs across 4,085 users; 13 of 4,098 users had no derived leaf. Counts include all user rows; no active-account filter was applied. This is a current aggregate candidate baseline only: it does not reproduce every route's role/global exception, compare target UUID scopes per user, prove crosswalk parity, or come from an immutable migration snapshot. User identifiers/names were not output.

The proposed `Organization-Scope.md` contract—five-level grants, union, filter intersection, explicit global grant, deny-by-default—is a design proposal and does not prove parity with deployed user access. Role action mapping, active-user rules, admin/global exceptions, historical reparenting and account activation require owner review. Never widen grants to compensate for missing crosswalk.
